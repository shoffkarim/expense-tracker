# Локальный учёт финансов — реализованная схема

## Компоненты

React + TypeScript + Vite: два экрана (`#/dashboard`, `#/import`), общие диалоги счетов/категорий/операций, черновик импорта в памяти приложения. Хранилище браузера не используется.

Go + `net/http`: парсер Poppler, API справочников/истории/экранов/импорта, отдельный слой расчёта операций. SQLite через `database/sql` и `mattn/go-sqlite3`; выбран доступный локально драйвер с CGO вместо недоступного для загрузки `modernc.org/sqlite`.

## Хранение

- `accounts`: начальные и текущие остатки, оформление, архив.
- `categories`: расход/доход, оформление, архив.
- `transactions`: положительная сумма, тип, дата, счета/категория, описание/комментарий, источник импорта, признак удаления.
- `category_months`: материализованные итоги по категории и месяцу операции.
- `balance_adjustments`: остаток до и после ручной правки, без влияния на категории.
- `imports`: счёт, SHA-256 PDF, ключ идемпотентности, отпечаток полного запроса и результат.
- `import_rows`: неизменная идентичность исходной строки для поиска повторов после редактирования истории.

Версионная схема находится в `backend/schema.sql`; миграции выполняются атомарно при старте. Включены внешние ключи и WAL. Записи выполняются последовательно; чтение экранов и истории получает согласованный снимок.

## Инварианты

1. Любая сохранённая операция меняет текущий баланс независимо от даты; отрицательный остаток разрешён.
2. Месячные суммы меняются вместе с операцией. Чтение сводки не пересчитывает историю.
3. Перевод касается двух счетов и не меняет доходы/расходы.
4. Изменение/удаление операции отменяет её прежний эффект и при необходимости применяет новый.
5. Архив сохраняет историю. Архивные ссылки нельзя впервые назначить новой операции.
6. Импорт записывается целиком; ошибка откатывает записи, балансы и итоги.
7. Повтор сетевого запроса использует тот же ключ и тело; повторный PDF для того же счёта блокируется.
8. Возможные дубли и зеркальные стороны переводов требуют решения пользователя. Сопоставление переводов использует точную дату; разные даты проверяются вручную.
9. Черновик не сохраняется в базе; при переходе между экранами остаётся в памяти, при закрытии вкладки теряется.

## Проверки и ограничения

Go-тесты на временной SQLite покрывают расчёты, редактирование/удаление, ручной баланс, архив, повторные импорты, откат, конкуренцию, месяц и перезапуск. DOM-тесты React проверяют формы и поток импорта с потерей ответа. Opt-in тест пропускает локальный реальный PDF через HTTP-обработчик, импорт и повтор сохранения, не выводя финансовое содержимое.

Без аккаунтов, облака, других валют и OCR. Возвраты покупок — доход или перевод. Полноценная браузерная и визуальная приёмка требует локального запуска вне текущего ограничения sandbox на открытие порта.

Подробные контракты — [API.md](API.md); запуск и приёмка — [../README.md](../README.md).

## Теги

Версия схемы SQLite 3 добавляет общий справочник `tags` (уникальный нормализованный ключ) и связи `transaction_tags`. Создание названий и замена связей выполняются внутри транзакции сохранения операции/импорта/правила. Финансовые расчёты и банковские идентичности от тегов не зависят. Внешний контракт использует массив названий `tags`; старые запросы без тегов совместимы, PATCH операции без этого поля сохраняет связи.

При разборе выписки категория/перевод и сопутствующие теги берутся из первого подходящего правила с таким результатом. Другие правила с категорией/переводом пропускаются целиком. Правила только с тегами применяются независимо от позиции. История фильтруется по нормализованному тегу на сервере до подсчёта и пагинации.
