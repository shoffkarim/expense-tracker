# Работа с expense-tracker

Локальное приложение учёта финансов: React + TypeScript + Vite, Go + SQLite и Poppler для разбора PDF. Общение и пользовательские тексты — на русском языке.

## Карта проекта

- `frontend/src/` — интерфейс: обзор (`Dashboard.tsx`), импорт (`ImportScreen.tsx`, `ImportPicker.tsx`), правила (`Rules.tsx`), формы и API-клиент.
- `frontend/test/` — тесты React в JSDOM с подменённым HTTP, запускаемые встроенным тестовым раннером Node.js.
- `backend/` — Go-модуль: HTTP в `main.go` и `api_handlers.go`, хранение в `store.go` и `schema.sql`, операции в `ledger.go`, импорт в `imports.go`, правила в `rules.go`.
- `backend/parser.go` — старый формат «Выписка по договору»; `parser_v2.go` — «Справка о движении средств». Сохраняйте поддержку обоих форматов.
- `docs/API.md` — API-контракты; `docs/PLAN.md` — устройство реализации; `README.md` — запуск и пользовательские правила.

## Запуск и проверки

Нужны Go 1.26+, Node.js 20.19+ или 22.12+, Poppler и C-компилятор; SQLite-драйвер требует CGO.

Из корня `./start.sh` собирает фронтенд и запускает приложение на `http://127.0.0.1:8080`. Запуск открывает пользовательскую базу; для экспериментов используйте отдельную временную базу через флаг `-db`.

Команды проверки запускаются из соответствующих каталогов, корневого `package.json` нет:

```sh
cd backend
go test -race ./...
go vet ./...
cd ../frontend
npm test
npm run build
```

`npm run build` включает проверку TypeScript. В ограниченной среде можно задать `GOCACHE=/private/tmp/expense-tracker-go-cache`. Ошибка привязки порта sandbox не подтверждает успешный запуск приложения. UI-тесты не заменяют проверку в браузере.

## Инварианты и безопасность данных

- Деньги храните и считайте в целых копейках в пределах безопасных целых JavaScript; не используйте дробные рубли для вычислений.
- Сохраняйте атомарность операций, балансов и итогов категорий, идемпотентность импорта и проверку повторов. Переводы не должны увеличивать доходы или расходы категорий.
- Изменения схемы проводите через существующий механизм версионных миграций с сохранением данных.
- Не читайте и не меняйте пользовательскую базу в `data/` без необходимости для задачи. Тесты должны использовать временные базы и синтетические данные.
- Не коммитьте и не выводите в логи банковские PDF/XML, финансовые эталоны, содержимое операций, базы SQLite и их служебные файлы. Не изменяйте оригиналы документов в `docs/`.
- Проверки на реальных PDF выполняйте только при необходимости; параметры описаны в README. Не переносите реальные финансовые данные в фикстуры.
- Сохраняйте локальный характер приложения, ограничения host/origin и удаление временных PDF/XML после обработки.
