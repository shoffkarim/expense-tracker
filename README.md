# Выписка

Локальный учёт финансов: React + TypeScript + Vite + Mantine, Go + Poppler и SQLite. Без аккаунтов и облака. Поддерживаются рублёвые операции в двух форматах банковской PDF-выписки: «Выписка по договору» и «Справка о движении средств». Формат определяется автоматически по заголовку и колонкам таблицы.

## Запуск

Нужны Go 1.26+, Node.js 20.19+ (или 22.12+), Poppler и C-компилятор для SQLite-драйвера. На macOS компилятор входит в Xcode Command Line Tools (`xcode-select --install`). `CGO_ENABLED` должен быть равен `1`.

```sh
./start.sh
```

Открыть **http://127.0.0.1:8080**. Скрипт собирает фронтенд и запускает Go. Он находит системный `pdftotext` либо локальный `.tools/poppler/bin/pdftotext`. Если Poppler не установлен: `brew install poppler`. Скачивание зависимостей при первом запуске требует сети; работа приложения выполняется локально.

База создаётся автоматически в `data/expense-tracker.sqlite`. Для другого пути запустите сервер из `backend`:

```sh
go run . -pdftotext ../.tools/poppler/bin/pdftotext -db /путь/к/ledger.sqlite
```

Схема обновляется при запуске версионными миграциями; новая версия базы не открывается старым приложением. Для резервной копии остановите приложение и скопируйте всю папку `data`, включая служебные файлы SQLite, если они присутствуют.

## Как пользоваться

**Обзор** (`#/dashboard`) показывает общий баланс активных счетов, сами счета и категории расходов/доходов за текущий календарный месяц. Здесь можно добавить или изменить счёт, категорию и операцию. Ниже — история с фильтрами по датам, счёту и категории и страницами по 30 операций. Нажатие на операцию открывает редактирование и удаление.

**Выписка** (`#/import`) — выберите счёт, загрузите PDF и распределите строки:

- списание: категория расхода либо другой свой счёт;
- поступление: категория дохода либо счёт-источник;
- ненужная строка: «Не импортировать»;
- возможный повтор: пропустить или явно выбрать «Сохранить как отдельную операцию».

Кнопка сохранения появляется после распределения всех непропущенных строк и разбора совпадений. Пакет сохраняется целиком вместе с балансами и итогами. Если одна строка некорректна, ничего из пакета не сохраняется. После успешного импорта черновик очищается.

Черновик сохраняется при переключении экранов, но исчезает при перезагрузке или закрытии вкладки. Перед уходом браузер предупреждает о несохранённой выписке. PDF/XML не сохраняются в базе.

Если ответ на сохранение потерялся, «Повторить сохранение» отправляет исходный запрос с тем же ключом. Это не создаёт операции повторно. Пока результат неизвестен, редактирование черновика заблокировано.

## Правила расчёта

- Все деньги — целые копейки, без вычислений с дробными рублями. Максимальное абсолютное денежное значение — `9007199254740991` копейка, в пределах точных целых JSON/JavaScript.
- Начальный баланс задаётся при создании счёта. Любая сохранённая операция изменяет текущий баланс независимо от своей даты. Отрицательный остаток разрешён.
- Ручная правка остатка создаёт отдельную корректировку и не увеличивает доходы/расходы. Последующее редактирование старой операции изменяет текущий остаток на разницу между её прежним и новым эффектом.
- Расход уменьшает счёт, доход увеличивает счёт. Перевод уменьшает один счёт и увеличивает другой, не попадая в категории расходов и доходов.
- Итоги категории хранятся отдельно для каждого `YYYY-MM` и меняются при добавлении, изменении и удалении операций. Месяц определяется датой операции. Полная история при показе сводки не суммируется.
- Текущий месяц определяется локальным часовым поясом сервера; даты операций не переводятся в UTC. Сводка обновляется после изменений, при возвращении в приложение и смене месяца.
- Архивирование счёта исключает его из общего баланса и выбора для новых операций. История и остаток сохраняются. Существующие операции с архивными ссылками можно исправлять и удалять.
- Архивные категории с ненулевой суммой текущего месяца остаются в сводке. Тип существующей категории (доход/расход) неизменяем.
- Удаление операции отменяет её эффект и скрывает её из истории. Техническая связь с импортом остаётся для поиска повторов. Восстановления из интерфейса пока нет.

Начальные категории: Еда, Дом, Машина, Медицина, Прочее; доходы: Зарплата, Инвестиции, Подарки, Прочее. Можно создавать собственные категории.

## Повторные выписки и переводы

Один и тот же PDF для одного счёта сохраняется только один раз, включая частично пропущенный пакет. Исправления и недостающие операции добавляются через историю/ручную форму; повтор файла целиком не используется для дозагрузки.

В пересекающихся выписках приложение ищет совпадения по счёту, дате, сумме со знаком и нормализованному описанию. Ищутся как текущие операции, так и исходные сохранённые строки, даже если операция позже исправлена или удалена. Похожие строки внутри одного PDF тоже подсвечиваются.

Для возможной стороны перевода сопоставляются счёт, точная дата и сумма с нужным направлением; описание может отличаться. Автоматического объединения нет: пользователь решает, что пропустить. Если банк провёл стороны перевода в разные дни, их нужно распознать вручную. Пропущенные строки не создают операций. Повторная проверка перед записью не позволяет молча сохранить новые совпадения со старым подтверждением.

Возврат покупки пока учитывается как доход либо перевод; отдельного типа возврата с уменьшением расходной категории нет. Других валют, OCR, синхронизации и авторизации нет.

## Разработка

В первом терминале:

```sh
cd backend
go run . -pdftotext ../.tools/poppler/bin/pdftotext
```

Во втором:

```sh
cd frontend
npm ci
npm run dev
```

Открыть http://127.0.0.1:5173. Vite проксирует `/api` в Go. Оба сервера слушают loopback; production-фронтенд раздаётся Go с того же origin.

SQLite подключён через `database/sql` и `github.com/mattn/go-sqlite3 v1.14.22`. Вместо первоначально выбранного `modernc.org/sqlite` использован доступный локально драйвер: загрузка нового пакета была недоступна. Включены внешние ключи, WAL, `synchronous=FULL`, ожидание блокировки до 5 секунд и последовательные транзакции записи. Схема — `backend/schema.sql`, версия — `PRAGMA user_version`.

Если после копирования проекта `npm run build` не находит `../lib/tsc.js`, восстановите ссылки командой `npm rebuild --offline --ignore-scripts` в `frontend`.

## Проверки

```sh
cd backend
go test -race ./...
go vet ./...
cd ../frontend
npm test
npm run build
```

Go-тесты работают с отдельными временными базами и синтетическими данными. Проверяют денежные изменения, старые даты, смену месяца, исправления, архив, атомарность, идемпотентность, совпадения и конкурентные записи. UI-тесты используют React + JSDOM и подменённый HTTP: ввод денег, формы, категоризацию, переключение экранов и повтор после потери ответа. Они не заменяют визуальную проверку браузера.

Дополнительная проверка реального PDF через HTTP-обработчик без открытия порта:

```sh
cd backend
EXPENSE_TRACKER_TEST_PDF=../docs/bank.pdf \
EXPENSE_TRACKER_PDFTOTEXT=../.tools/poppler/bin/pdftotext \
go test -run TestRealStatementImport -v
```

Она разбирает файл, сохраняет операции во временную базу, проверяет итоговый баланс и повтор запроса. Содержимое и суммы операций не выводятся. Без переменной окружения этот тест пропускается.

Для нового формата можно дополнительно проверить число операций и первые семь строк по локальному эталону текущего API:

```sh
cd backend
EXPENSE_TRACKER_TEST_PDF=../docs/bank_v2.pdf \
EXPENSE_TRACKER_TEST_COUNT=95 \
EXPENSE_TRACKER_TEST_EXPECTED=../docs/expenses_test_v2.json \
EXPENSE_TRACKER_PDFTOTEXT=../.tools/poppler/bin/pdftotext \
go test -run TestRealStatementImport -count=1 -v
```

`EXPENSE_TRACKER_TEST_COUNT` и `EXPENSE_TRACKER_TEST_EXPECTED` необязательны. Эталон имеет форму `{ "transactions": [...] }` и сравнивается с началом результата, включая дату, описание, сумму в копейках, страницу и номер строки. Для старого образца ожидаемое число операций — 69. Оба финансовых эталона исключены из Git; обычные тесты парсера используют синтетические данные.

При добавлении второго формата прошли Go-тесты с `-race` и `go vet`. Старый образец дал **69 операций**, новый — **95 операций**, оба без предупреждений; первые семь новых операций полностью совпали с эталоном. Полный результат старого парсера сохранился. Для обоих образцов прошли импорт во временную базу, проверка баланса и идемпотентный повтор.

UI-тесты и production-сборка проходили при первоначальной реализации; при обновлении парсера фронтенд не менялся. Загрузка через настоящий браузер остаётся непроверенной: предыдущая попытка запуска HTTP-сервера была заблокирована sandbox (`bind: operation not permitted`).

## Данные и API

Контракты запросов: [docs/API.md](docs/API.md). Устройство реализации: [docs/PLAN.md](docs/PLAN.md).

Сервер принимает запросы только на локальные host/origin. Исходные PDF/XML временные и удаляются после обработки, включая ошибки. Операции, описания и документы не логируются. База и служебные файлы, PDF и финансовые образцы исключены из Git. Предоставленные оригиналы в `docs` приложение не меняет.

## Правила распределения

На странице «Правила» можно создавать, менять, удалять и перемещать правила выше/ниже. Первое подходящее правило с категорией или переводом выбирает категорию расхода, источник дохода или другой свой счёт для перевода. Правила только с тегами добавляют теги независимо от позиции. Условия: подстрока в описании выписки без учёта регистра и лишних пробелов либо день месяца и точная сумма. Направление задаётся отдельно; сумма вводится положительной. Правило действует для всех счетов или одного выбранного.

Выберите счёт перед загрузкой PDF. Автоматическое назначение можно изменить вручную. Изменение правил влияет только на новые загрузки; смена счёта требует подтверждения сброса черновика. Архивные счета и категории делают связанные правила недоступными. Правила хранятся локально в SQLite; обновление схемы до версии 3 сохраняет ранее внесённые данные.

### Теги операций

У операции может быть несколько тегов, например «кофе» и «работа». Выберите существующий тег или введите новый в форме операции, строке распознанной выписки или правиле. Enter добавляет тег, крестик снимает его с операции. Новое название сохраняется только вместе с формой; теги доступны для расходов, доходов и переводов. В истории фильтр по тегу работает самостоятельно и совместно со счётом, категорией и датами.

Правило может задавать только теги, только категорию/источник дохода/перевод или их сочетание. Первое подходящее правило с категорией или переводом применяется целиком, остальные правила с категорией или переводом пропускаются вместе с тегами. Подходящие правила только с тегами добавляют свои теги независимо от позиции. Правила действуют при загрузке новой выписки, существующие операции не меняются.

В распознанной выписке сумму можно изменить перед сохранением. Вводите положительную величину в рублях с точкой или запятой и не более чем двумя знаками после неё; направление операции сохраняется. После изменения совпадения проверяются заново. Исходно нулевые строки остаются пропущенными.

Разделение при импорте: «Разделить» создаёт две части с пустыми суммами; можно добавить части или отменить разделение. Сумма частей должна точно совпадать с исходной. В истории сохраняются только части. API принимает необязательный массив parts: amountMinor (со знаком родителя), categoryId либо otherAccountId, tags, comment. Дата и описание наследуются. Проверка дублей относится ко всей исходной строке.

Карточки счетов, расходов и доходов на обзоре можно переставлять перетаскиванием внутри своего блока. На сенсорном экране удерживайте карточку перед переносом. Порядок сохраняется локально и не меняет списки выбора в формах. Правила также можно перетаскивать или перемещать стрелками; их порядок определяет приоритет применения. Для клавиатуры: фокус на карточке, пробел, стрелки, пробел для завершения или Escape для отмены.
